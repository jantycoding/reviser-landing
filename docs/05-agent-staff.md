# Штаб ИИ-агентов для доводки лендинга

22 агента, шесть отделов, один прогон = один полный цикл огранки.

---

## Как устроено

Работа идёт в изолированной копии проекта под git. Каждый агент видит общий
бриф (`BRIEF.md`) — бизнес-модель, воронку, дизайн-систему, технические ловушки
и красные линии. Файлы поделены между исполнителями так, что двое никогда не
правят один файл: иначе параллельная работа затирает сама себя.

```
Разведка (6)  →  Штаб (1)  →  Реализация (7)  →  Надзор (1)
                                                      ↓
     Приёмка (1)  ←  Доводка (3)  ←  Критика (4)
```

## Отдел разведки — 6 аналитиков

Работают параллельно, ничего не правят, только изучают. Каждый смотрит своим
взглядом, и это принципиально: один агент с шестью задачами найдёт втрое
меньше, чем шесть агентов с одной.

| Агент | Что ищет |
|---|---|
| **Психология** | Мотивация против трения, последовательность снятия возражений, момент решения о платеже |
| **Копирайт** | Понятность оффера за 5 секунд, конкретика против абстракций, язык предпринимателя, а не разработчика |
| **Визуальный дизайн** | Иерархия, ритм, композиция экранов, работа трёх цветов, шаблонность |
| **Мотион** | Где движение помогает понять продукт, где оно шум, есть ли запоминающийся момент |
| **Технический QA** | Сборка, застрявшие анимации, переполнение, кегли, доступность, якоря |
| **Путь к оплате** | Сколько экранов до понимания, до цены, до кнопки; сколько кликов и полей |

Каждый обязан собрать страницу, снять скриншоты и **посмотреть их глазами** —
судить по коду запрещено.

## Штаб — начальник

Получает все находки разом. Убирает дубли (одна проблема всплывает у трёх
аналитиков под разными именами), отсеивает противоречащее брифу, сортирует по
влиянию на оплату — не по красоте, — и раскладывает по исполнителям в виде
приказов: что сделать, в каком файле, какого результата ждать. Не больше шести
задач на исполнителя за раунд.

## Отдел реализации — 7 исполнителей

Сначала двое работают с общими файлами, потом пятеро расходятся по секциям.

| Исполнитель | Владеет файлами |
|---|---|
| **copy** | `content/site.js` — весь текст страницы |
| **tokens** | `index.css`, `ui/*` — дизайн-система |
| **hero** | `Hero.jsx`, `Header.jsx` |
| **agents** | `Agents.jsx`, `Platforms.jsx` |
| **gate** | `Gate.jsx`, `Audit.jsx` |
| **report** | `Report.jsx`, `ReportPanel.jsx`, `Process.jsx` |
| **convert** | `Pricing.jsx`, `Faq.jsx`, `Checkout.jsx`, `Footer.jsx` |

Каждый собирает проект в свой отдельный каталог — иначе параллельные сборки
дерутся за `dist/`. Увидел проблему в чужом файле — не трогает, пишет в отчёт.

## Надзор — 1 агент

Не верит отчётам: смотрит `git diff` и сверяет с нарядом. Отчёт «сделано» без
изменений в файле — невыполненная задача. Проверяет, что никто не залез в чужую
зону, что сборка жива, что не нарушены красные линии.

## Отдел критики — 4 критика

Самая ценная часть. Работают по уже сделанному, задача — найти слабое.

**Клиент.** Играет роль: Ерлан, 38 лет, три автомойки в Алматы, оборот 12 млн ₸,
в ИИ не разбирается, дважды обжигался на «автоматизации». Листает только с
телефона, скриншот за скриншотом. Отвечает не как эксперт, а как человек: где
закрыл бы вкладку, чему не верит, что остановило от оплаты.

**Воронка.** Где обещание без доказательства, где просим доверие раньше, чем
заслужили, где возражение возникает раньше, чем мы его снимаем. Отдельно
проверяет, снято ли главное невысказанное: «вы найдёте проблемы, чтобы продать
внедрение за 600 тысяч».

**Дизайн.** Ритм, иерархия, сетка, плотность, консистентность. Ключевой вопрос:
выглядит ли это как компания, которой можно отдать доступ к своей CRM, или как
шаблон.

**QA.** Проверяет руками через браузер: кликает каждый пункт меню и каждую
кнопку, раскрывает FAQ, заполняет форму, ходит табом, снимает пять разрешений
от 320 до 1920px. Репортит только воспроизведённое.

## Отдел доводки — 3 агента

Получают все замечания критиков разом. Отбирают свои, отсеивают противоречащие
брифу, чинят по приоритету: блокеры, потом major, minor — если остаётся запас.
Поделены так же по владению файлами: текст, дизайн-система, разметка.

## Приёмка — 1 агент

Решает, можно ли лить платный трафик. Пересобирает, прогоняет страницу в
браузере на десктопе и мобильном, смотрит все скриншоты, проверяет якоря,
красные линии и объём изменений за сессию. Выдаёт акт.

---

## Правила, без которых штаб съедает сам себя

**Один файл — один владелец.** Двое параллельных агентов в одном файле =
потерянная работа. Все правки текста только через `copy`, все правки токенов
только через `tokens`.

**Общие файлы — до секционных.** `site.js` и `index.css` правятся первыми, пока
остальные ждут. Иначе секционный агент верстает под текст, которого через
минуту не станет.

**Скриншоты обязательны.** Агент, который судит о дизайне по коду, бесполезен.

**Надзор не верит отчётам.** Модель охотно пишет «сделано». Проверка — только
по диффу.

**Красные линии повторены в каждом промпте.** Не выдумывать цифры и кейсы, не
ставить чужие логотипы как клиентские, не просить пароли, не класть секреты в
`VITE_`-переменные. Один агент, который об этом не знает, откатывает работу
всех остальных.

## Что можно донастроить между раундами

- число аналитиков в разведке и их ракурсы;
- лимит задач на исполнителя (сейчас 6) — больше задач за раунд, но выше риск
  поверхностного исполнения;
- портрет критика-клиента — под конкретную нишу из ваших креативов;
- добавить раунд «доводка → критика» ещё раз внутри одного прогона;
- добавить агента по скорости загрузки — после возврата GSAP и three это
  сейчас самая недообслуженная область.
