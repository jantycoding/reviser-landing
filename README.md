# Reviser — лендинг

Одностраничный сайт сервиса внедрения ИИ-агентов в бизнес.
Продаёт разбор бизнеса за 9 900 ₸ как первый шаг к внедрению.

**Стек:** React 19 · Vite 8 · Tailwind v4 · [react-bits](https://github.com/DavidHDev/react-bits)
**Хостинг:** Vercel (статика + serverless-функция для заявок)

---

## Быстрый старт

```bash
npm install
cp .env.example .env      # заполнить контакты — без этого кнопки WhatsApp ведут в никуда
npm run dev               # http://localhost:3000
```

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки на `localhost:3000` |
| `npm run build` | сборка в `dist/` |
| `npm run preview` | посмотреть собранную версию |
| `npm run lint` | oxlint по `src/` и `api/` |
| `npx vercel dev` | то же, что `dev`, но с работающей папкой `api/` |

**Важно:** `npm run dev` не поднимает serverless-функции. Форма заявки будет
уводить в WhatsApp, но заявка в Telegram не уйдёт — `/api/lead` вернёт 404.
Чтобы проверить весь путь целиком, нужен `npx vercel dev`.

### Правило владения файлами

Двое не правят один файл одновременно — иначе параллельная работа затирает сама
себя. Закреплено так:

| Файл / зона | Владелец |
|---|---|
| `src/content/site.js` — весь текст | Арсен |
| `src/index.css`, `src/components/ui/*` — дизайн-система | Жантемир |
| `src/sections/*` | тот, кто взял задачу в этом раунде |
| `api/*`, деплой, переменные окружения | Жантемир |
| `.env`, реквизиты, домен | Арсен |

## Переменные окружения

Полный список с пояснениями — в [`.env.example`](.env.example).

**Главное правило безопасности:** всё, что начинается с `VITE_`, вшивается в
JS-бандл и видно любому посетителю через «Просмотр кода». Туда можно класть
только публичное — номер телефона, id пикселя, почту. Секреты (токен бота,
ключи платёжного провайдера) идут **без** префикса `VITE_` и читаются только
серверными функциями из `api/`.

| Переменная | Обязательна | Что это |
|---|---|---|
| `VITE_WHATSAPP` | **да** | номер WhatsApp: `77011234567`, без плюса и пробелов |
| `VITE_EMAIL` | да | почта в подвале |
| `VITE_INSTAGRAM` | да | ссылка на профиль |
| `VITE_LEGAL` | да | реквизиты ИП строкой, как в оферте |
| `VITE_META_PIXEL_ID` | для рекламы | id пикселя Meta; без него пиксель не грузится вовсе |
| `VITE_PAY_ENDPOINT` | нет | адрес бэкенда оплаты; пока не задан — счёт выставляется вручную |
| `TELEGRAM_BOT_TOKEN` | для заявок | секрет, только в переменных Vercel |
| `TELEGRAM_CHAT_ID` | для заявок | секрет, только в переменных Vercel |

## Как работает форма заявки

Человек вводит имя и телефон в блоке `#checkout` и нажимает кнопку. Дальше
происходят две вещи одновременно:

1. Браузер уходит по ссылке `wa.me/<номер>?text=<готовое сообщение>` — в WhatsApp
   уже подставлены имя, телефон и что он хочет.
2. Параллельно через `navigator.sendBeacon` те же данные уходят на `/api/lead`,
   а оттуда — в Telegram.

Второй пункт существует потому, что переход в WhatsApp — это ещё не сообщение.
Человек может не нажать «отправить», у него может не стоять WhatsApp на
компьютере, он может отвлечься при переключении приложений. Раньше в этом
случае имя и телефон терялись безвозвратно — причём именно у тех, кто дошёл до
конца страницы.

`sendBeacon`, а не `fetch`: сразу после вызова браузер выгружает страницу, и
обычный запрос в этот момент отменяется — то есть не срабатывает ровно в том
сценарии, ради которого всё и делалось.

**Спам-фильтр:** в форме есть скрытое поле `company`. Человек его не видит,
автозаполнялка бота — заполняет. Заявки с непустым `company` бэкенд молча
отбрасывает. Плюс лимит 5 заявок в минуту с одного IP.

## Meta Pixel

Поднимается в `src/main.jsx` только если задан `VITE_META_PIXEL_ID`.
Без переменной на странице не появляется ни одного запроса к `facebook.net`.

События:

| Событие | Когда |
|---|---|
| `PageView` | загрузка страницы |
| `InitiateCheckout` | клик по кнопке в блоке `#checkout` |
| `Lead` | тот же клик, но только если человек оставил имя или телефон |
| `Contact` | клик по «написать в WhatsApp» в hero, FAQ и подвале |

`Lead` намеренно не вешается на каждый клик по WhatsApp: если пометить им кнопку
в подвале, алгоритм Meta будет искать любопытных, а не покупателей.

## Технические ловушки этого проекта

Три вещи, которые уже ломали страницу. Не наступайте повторно.

**1. WebGL-фон импортируется только через `lazy()`.**
`FloatingLines` тянет за собой three.js — это ~485 КБ. Прямой `import` кладёт их
в основной чанк, и первый экран не показывается, пока весь three не скачается.
Сейчас: 410 КБ основной чанк + отдельный чанк с three, который догружается после
текста. Было 893 КБ одним куском.

**2. Имя spacing-токена не должно совпадать с ключевым словом `display`.**
В Tailwind v4 пространство имён `--spacing-*` порождает не только `p-<value>`,
но и логическое свойство `inline-<value>` → `inline-size`. Токен `--spacing-block`
создавал второе правило `.inline-block{inline-size:72px}`, которое перебивало
`display:inline-block`. Запрещённые имена: `block`, `inline`, `flex`, `grid`,
`table`, `contents`.

**3. `overflow-x: clip` на `<html>` ломает переход по якорям.**
Клик по пункту меню менял URL и не двигал страницу. Горизонтальное переполнение
даёт только бегущая строка — клипается она, а не корень документа.

**4. Базовое состояние элемента — видимое.**
Прятать элемент имеет право только код, который гарантированно покажет его
обратно. Reveal-анимации на `IntersectionObserver` + CSS, со страховкой: если
через 1.8 с блок во вьюпорте всё ещё скрыт — показываем принудительно.

## Красные линии

Нарушение любой из них стоит дороже, чем весь выигрыш от нарушения.

- **Не выдумывать цифры, кейсы и отзывы.** Продукт продаёт честность выводов —
  пойманная выдумка на главной убивает позиционирование разом.
- **Не ставить чужие логотипы в роли клиентских.** Это нарушение рекламной
  политики Meta (а весь трафик оттуда), претензии по товарным знакам и потеря
  доверия рынка, где предприниматели общаются между собой.
- **Не просить у клиентов пароли.** Только гостевой доступ на чтение. Meta,
  amoCRM и Bitrix прямо запрещают передачу учётных данных; вход в чужой кабинет
  по паролю — типовой триггер блокировки обоих аккаунтов.
- **Не класть секреты в переменные с префиксом `VITE_`.**
- **Не публиковать страницу с заглушками в контактах и реквизитах.**
